# Changelog

All notable changes to the Shield360 .NET SDK will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

First release of the .NET SDK, as version 0.1.0.

### Added
- RASP protection against AI attack agents (`sdk/rasp/README.md` "AI attack agents"): new attack type `RaspAttackType.AiAttackAgent` (`ai_attack_agent`, default monitor). Fingerprints (`attackAgentHeaders`, `attackTools`), inbound OAST callback domains (dual-use `inboundSkip` left out), the in-app behavior score per address (/64) and per user (`Shield360Rasp.IdentifyUser`), the opt-in LLM tripwire on decoy pages, the deter answer (429 with `Retry-After`) in block mode and a signed Edge block verdict. The signed `attackAgents` block, else `RaspOptions.AttackAgents`. Requests Edge verified, or of an authorized red team run (`rt`), are left alone. Client types `ai_attack_agent` and `scanner` (`ClientType.Classify`), subtypes of `unverified_automation` in Defend rules. Passes `sdk/rasp/testdata/ai-attack-agents.json`. A RASP block's signed Edge verdict now survives the middleware's 403.
- Upload protection (`sdk/rasp/README.md` "Uploads"), all four layers: inspection (real type, zip/tar, Office macros and OLE, polyglots, active content, EICAR, the built-in web-shell signatures as a byte-identical `upload-signatures.json`, the organization's own signatures; passes `sdk/rasp/testdata/uploads.json`), the signed `uploads` policy (`RaspUploads.OptionsFor`, `RaspOptions.Uploads`), the deep scan (clamd zINSTREAM over TCP and Unix sockets, hash-only reputation, sync/async, quarantine, fail closed, `shield360.rasp.scanner` status) and the backdoor checks through `RaspFile`, the process checks, `CheckChmod`, `CheckLoad` and `CheckExtract`. The ASP.NET Core middleware inspects each multipart file before the app. New attack types `malicious_upload` and `upload_backdoor`.
- Shield360 Defend (`Shield360.Defend.Shield360Defend`, `app.UseShield360Defend` in Shield360.AspNetCore): the signed Defend policy (`/api/defend/policy`, typ `shield360-defend+jws`, pinned and cached like the RASP config), deny/challenge/trust lists, rules (paths, methods, countries, ASNs, client types, prompt injection, rates), the decisions feed, shared rate limits, reporting to `/api/defend/report`, client type from the shared signatures, traps, honeypot crumbs byte for byte the Edge spec, and the content check (the shared prompt-injection detector, held to the Go detector's golden corpus, and the PII/secret shapes).
- Protection triangle (`agent-guides/edge-deception-spec.md`, "Protection triangle"): the ASP.NET Core middleware verifies Shield360 Edge's signed `X-Shield360-Edge-Context` header with the signed config's `edgeContext` keys, cross-checked against Edge's own `X-Request-Id`. A client Edge marked (flagged, trap level 2+, risk 70+, unless a verified crawler or agent) is blocked for injection-class attacks the app only monitors (`shield360.rasp.tightened_by_edge`); events carry `shield360.edge.request_id`; the first finding is answered with a signed `X-Shield360-Verdict` response header. Passes `sdk/rasp/testdata/triangle.json`.
- Request correlation: Edge's request id (verified context, else an id-shaped `X-Request-Id`) goes on the ASP.NET Core server span (enrich hook) and on every `ILogger` record as `shield360.edge.request_id`, with the trace id of the request's `traceparent` as `shield360.edge.trace_id` when no span is active. Passes `sdk/rasp/testdata/request-correlation.json`.
- Data store and RPC tracing with no new dependencies: MySqlConnector commands, MongoDB.Driver 3.x operations and Grpc.Net.Client calls are traced from the libraries' own ActivitySources inside the request trace. gRPC spans get the OpenTelemetry `rpc.*` attributes and are named `Service/Method`. SQL keeps no parameter values, MongoDB no query text, gRPC no messages. Turn each off with `mysqlconnector`, `mongodb` or `grpc` in `DisabledInstrumentors`.
- RASP deception (contract "Deception"): the signed config's `deception` block (decoy paths, `action`, `ttlSeconds`) is read and the ASP.NET Core middleware checks decoys before anything else and never lets one reach an endpoint: with `AddShield360Rasp` or zero-code setup routing matches nothing for it, so the app's own not-found handling (status code pages, re-execute) answers it like an unknown path; `UseShield360Rasp()` alone answers ASP.NET Core's empty 404 (`deception.hit`, sink `http.deception`), and marks the client address `request.ip` uses as suspicious, in memory per process (at most 10,000, ordered by expiry; when full, expired marks go first, then the one closest to expiring). A later request from it is `deception.suspicious`, answered with the 403 when the action is `block`. New attack type `RaspAttackType.Deception`: `off` turns it off, `monitor` caps it, unset leaves it to the action. Fails open. Passes `sdk/rasp/testdata/deception.json`.
- Masking follows the shared contract (`sdk/rasp/README.md`, "Masking"; cases in `sdk/rasp/testdata/masking.json`) for RASP snippets and application logs: quoted and JSON credentials and `Authorization` schemes are masked, a value is masked before it is cut, and readable identifiers (class names, package and file paths) are no longer masked as long tokens.
- Application logs, opt-in with `Shield360Options.CaptureLogs` or `SHIELD360_CAPTURE_LOGS=true` (`LogLevel` / `SHIELD360_LOG_LEVEL`, `info` by default): `ILogger` records go over OTLP/HTTP to the same endpoint, headers and resource as traces (`/v1/logs`), with the active trace and span ids. `Shield360Sdk.LoggerFactory` and `Shield360Sdk.CreateLogger()` after `Init()`, `AddShield360()` for the host's logging, `ILoggingBuilder.AddShield360Logs()`, and forwarding under the zero-code start. The same rules as the Python SDK: OpenTelemetry short severity names, masking by the shared contract (`sdk/rasp/README.md`, "Masking": credential pairs, bearer credentials and opaque tokens masked, fields named like credentials masked whole, lists and maps item by item, readable identifiers kept, masked before the cut), the SDK's and OpenTelemetry's own categories and records written during export never sent, at most 500 records a second, batched, and failing open.
- `Shield360Rasp.CheckTemplate(engine, source)`: `code.template_injection` for request input in a template's source, checked before Scriban (`"scriban"`), Fluid (`"liquid"`) or Handlebars.Net (`"handlebars"`) parses or compiles it. Uses the shared engine table `sdk/rasp/rules/template-engines.json` and passes the `template` corpus section and `template-attack-examples.json`.
- RASP SQL lexer dialects `RaspSqlDialect.Oracle` and `RaspSqlDialect.Db2` (contract "SQL"): Oracle `q'[…]'` / `nq'…'` alternative quoting, `:1` binds and `#` in identifiers, no backslash escapes; Db2 `X'…'`, `G'…'`, `GX'…'`, `UX'…'` and `BX'…'` strings. SQL Server `[…]` identifiers now honor the `]]` escape, and block comments nest in Db2, PostgreSQL and SQL Server. The Oracle `q'…'` delimiter may be any non-whitespace character, multibyte included. Passes the shared `sdk/rasp/testdata/sql-lexer.json`.
- Runtime application self-protection (RASP), piece 1 of the port of the TypeScript SDK's RASP (contract: `sdk/rasp/README.md`). Opt-in with `Shield360Options.Rasp`, `services.AddShield360Rasp()` or `SHIELD360_RASP=monitor|block`. It covers: the request context in an `AsyncLocal`; input capture and normalization; model output from `UseShield360()` as untrusted input; every structural detector with the contract's rule ids (it passes the shared benign corpus with no false positives and detects every entry of `attack-examples.json`); virtual patches with `runtimes` and `runtimeVersions` for `dotnet`; the Ed25519-signed remote config with key pinning, cache and polling; events and the components report sent to `/api/guard/events`; and the `Shield360Rasp.Disable()` / `Enable()` kill switch.
- RASP sink hooks, ported from the TypeScript hooks. Automatic: every `HttpClient` request (outbound allow-list and SSRF before sending) and every Microsoft.Data.SqlClient / System.Data.SqlClient command (SQL injection), through the diagnostic events those libraries raise before the call; turn them off with `RaspOptions.Hooks = false`. Opt-in: `Shield360RaspHttpHandler`, `Shield360RaspHttp.CreateHandler()` and `AddShield360Rasp()` / `AddShield360RaspHttpClients()` for `IHttpClientFactory`, which also check the addresses a connection actually uses (DNS rebinding) through `SocketsHttpHandler.ConnectCallback`; `Shield360Rasp.StartProcess`, `CheckProcess` and `CheckCommand`; `RaspFile` and `RaspDirectory`; `RaspXml`, `CheckXml`, `CheckDeserialization`, `CheckJson` and `CheckCode`; `CheckSql`, `CheckMongo`, `CheckPath` and `CheckUrl`. The check before sending also resolves a host an input names, so pooled connections, proxies and HTTP/3 are address-checked; redirect hops are checked again. The legacy SqlClient `Begin*` methods raise no diagnostic event and are not checked. The ASP.NET Core middleware now reports reflected input in HTML responses (`xss.reflected`, monitor only), including route values and model output. A .NET port of the hook test kit runs every hook through the same contract checks.
- RASP security baseline, ported from the TypeScript SDK: once per process, on the thread pool after RASP starts, monitor-only `baseline` events (sink `startup`) for a `ServicePointManager` certificate callback that accepts every certificate, a debugger attached in production, a Development host environment (the host's own `IHostEnvironment` when known) while the SDK says production, running as root or an elevated administrator, an unpinned config key in production, and an end-of-life .NET line. `RaspAttackType.Baseline` joins `Xss` as an attack type that never blocks.
- RASP upload file names, ported from the TypeScript SDK: the ASP.NET Core middleware records each uploaded file name (at most 32, from the first 1 MiB) as input `body.<field>.filename` and checks it for a script name (`file_write.upload`, sink `request.upload`), so a later write named after the upload is caught by `file_write.script`. Names come from `Request.Form.Files` when the form was already read, otherwise from the part headers of the buffered body, parsed with `MultipartReader`.
- RASP custom rules, ported from the TypeScript SDK (contract "Custom rules"): the signed config's `customRules` are parsed, type-checked and evaluated as data with the shared expression language (fields, comparisons, `in`, string methods, a linear-time regex subset on a Pike VM, CIDR), with the platform's limits and error codes. Request rules run with the virtual patches; finding rules run on built-in findings. Matches are `custom_rule` events (rule `custom.<id>`), capped by the new `RaspAttackType.CustomRule` mode. Invalid rules are skipped with one log line. Passes `sdk/rasp/testdata/custom-rules.json`. `request.ip` is ASP.NET Core's `Connection.RemoteIpAddress` when judged; rules that read it are judged again when forwarded headers set the client address, and wait for it behind a proxy trusted by `ForwardedHeadersOptions` configured in services. `custom_rule: off` evaluates no rule. Finding rules on capture-time findings (virtual patches, upload checks) see the request and share its budget. Head rules see only the inputs known before the body; an absent or empty body is a known, empty body, so body rules run on it.
- RASP passive IAST, ported from the TypeScript SDK (contract "Passive IAST"): `RaspOptions.Iast`, `IastSampleRate`, `SHIELD360_IAST` and the signed config's `iast` / `iastSampleRate` turn on `shield360.rasp.vulnerability` reports where request input reaches a sink unparameterized during normal traffic, with the contract's fingerprint, hourly dedupe, sampling and code location (the top app frame from `StackTrace`). Never blocks and never sends values; reports go to the reporter with no fold key, so a refused report is retried by IAST alone with its full count. Passes `sdk/rasp/testdata/iast.json`.
- RASP allow-list targets (contract "Allow-list targets"): with the signed config's `reportTargets: true`, `shell_spawn.shell`, `outbound.not_allowed` and `path.outside_root` events carry `shield360.rasp.target`, with credentials, `@` segments and long tokens masked and the attribute left out past 256 characters (never cut); every SQL finding carries `shield360.rasp.sql.dialect`. Passes `sdk/rasp/testdata/targets.json`.
- `Shield360Rasp.CheckAssemblyLoad(nameOrPath)`: `code.include` for an assembly name or path from input, checked before `Assembly.Load*`.
- `Shield360.EntityFrameworkCore`: a new package with `optionsBuilder.AddShield360Rasp()`, an EF Core command interceptor that checks the SQL of every command before it runs, in the provider's dialect.
- Dependency: `Microsoft.Extensions.Http`, for the `IHttpClientFactory` registration of the RASP outbound check.
- `Shield360.AspNetCore`: a new package with `AddShield360Rasp()` and `UseShield360Rasp()`. It captures each request's input, runs virtual patches before the endpoint and returns the contract's 403 for a block.
- Zero-code setup: `Shield360.StartupHook`, for `DOTNET_STARTUP_HOOKS`, starts Shield360 from environment variables before `Main` in an app that does not reference it, and a hosting startup in `Shield360.AspNetCore` (`ASPNETCORE_HOSTINGSTARTUPASSEMBLIES`, set by the hook) adds the RASP middleware with no code. A later `Shield360Sdk.Init()` or `AddShield360()` is then a no-op. On .NET 8 and 9, `DOTNET_ADDITIONAL_DEPS` and `DOTNET_SHARED_STORE` bring in the newer framework assemblies Shield360 needs (the build writes `Shield360.AdditionalDeps.deps.json` and `store/` next to the hook).
- Dependency: `BouncyCastle.Cryptography`, for Ed25519 verification of the signed RASP config.
- Feature flags: `Shield360Sdk.Flags` and `FlagsClient` poll `GET /api/flags/rules` (ETag, 30-second jittered interval) and evaluate locally with `FlagEngine`, a port of the shared flags engine (segments included) that passes `sdk/flags-core/testdata/vectors.json`. `GetFlagDetail`, `GetBool`, `GetString`, `GetNumber`, `GetJson` and `IsEnabled` never throw and return the caller's default until rules arrive; the served variation is set as `shield360.flag.<key>` on `Activity.Current`. AI helpers: `Model`, `KillSwitch` and `PromptAsync` (a flag that picks a Prompt Hub prompt).
- Published to NuGet as `Shield360` from the public mirror `Shield360-AI/shield360-dotnet`, with NuGet trusted publishing, Source Link and a symbols package. `Shield360Sdk.Version` now comes from the project's `<Version>`.
- `Shield360Sdk.Init` and `Shutdown` for console apps, and `services.AddShield360()` for hosted apps, exporting traces and metrics over OTLP/HTTP. Options fall back to the same environment variables as the Python, TypeScript and Go SDKs.
- `AddShield360Instrumentation()` for tracer and meter providers you configure yourself.
- `chatClientBuilder.UseShield360()`: a Microsoft.Extensions.AI middleware that records GenAI spans with token usage, cost and tool calls, and the GenAI metrics, for streaming and non-streaming calls.
- Collection of the GenAI telemetry built into Microsoft.Extensions.AI, the OpenAI .NET SDK (and Azure.AI.OpenAI), Azure.AI.Inference and Semantic Kernel, with their telemetry switches turned on.
- A span processor that adds `service.name`, `deployment.environment`, `telemetry.sdk.name` and `gen_ai.usage.cost` to those libraries' spans, prices nested GenAI spans once, and removes message content unless capture is on.
- `Pricing`: the bundled pricing data, or pricing from a URL, file or JSON string, with per-model overrides.
- `RuleEngineClient` and `Shield360Sdk.EvaluateRuleAsync`, matching the Go SDK's `EvaluateRule`.
- `SemanticConventions`, with the same attribute names as the Go SDK.
- Message content is off by default; turn it on with `CaptureMessageContent` or `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true`.
